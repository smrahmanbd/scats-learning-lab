SUMO code

    SCATS in SUMO

    A SCATS-style controller written in Python that drives Eclipse SUMO through TraCI. It reads stop-line loops every second, runs tactical control in each intersection and strategic control per subsystem, and writes logs and figures for every lab on this site.

    Install and run

    Python 3.9 or newer. SUMO itself installs from pip, so no separate download is needed (a system SUMO with SUMO_HOME set also works).

    git clone https://github.com/smrahmanbd/scats-learning-lab.git
cd scats-learning-lab/sumo
python -m pip install -r requirements.txt      # eclipse-sumo, traci, sumolib, numpy, matplotlib

python foundation/03_fixed_vs_scats.py --gui   # watch SCATS in sumo-gui
python run_all.py                              # every lab, about 10 minutes
python tools/export_site_results.py            # copy figures and tables into the website

    Each script accepts --gui, --seed, --end (demand duration in seconds) and --out. Results go to sumo/results/<level>/.

    The test network

    network.build_corridor(n, spacing) generates an east-west arterial with n signalised intersections and a side street at each. Arterial approaches have three lanes (right+through, through, exclusive left) so the protected-turn phase has its own loop; side streets have two. Every lane entering a junction gets an induction loop 2 m before the stop line, named loop_<lane id>.

    Foundation
    1 intersection, 2 phases (A main, B side), off-peak / peak / off-peak, 1 hour.
    Advanced
    4 intersections, 300 m apart, 3 phases (A main, B protected turn, C side), two subsystems J1–J2 and J3–J4 that may marry, eastbound then westbound peak, buses every 4 minutes, 90 minutes.

    Core algorithms

    The website's JavaScript simulators use a line-for-line port of these functions (docs/js/engine.js).

    def degree_of_saturation(g, T, n, h):
    """DS = g'/g,  g' = g - (T - n*h)"""
    if g <= 0:
        return 0.0
    return max(0.0, (g - (T - n * h)) / g)

def reconstituted_flow(ds, g, mf):
    return ds * g * mf / 3600.0          # VK

def next_cycle_length(current, ds, p):
    desired = current * ds / p.target_ds if ds > 0 else p.l_min
    up = p.step_up_fast if ds >= p.fast_ds else p.step_up
    delta = max(-p.step_down, min(up, desired - current))
    return max(p.l_min, min(p.l_max, current + delta))

def predict_plan_ds(ds, g_now, g_plan):
    return {p: ds[p] * g_now[p] / g_plan[p] for p in ds}

class Voter:                              # 2 of 3 for splits, 4 of 5 for offsets
    def vote(self, choice):
        self.history.append(choice)
        if choice != self.current and list(self.history).count(choice) >= self.needed:
            self.current = choice
        return self.current

    How the controller runs

    Every simulation second the runner reads all loop and lane subscriptions in one TraCI call and passes them to Region.step():

    1. Transit requests: buses within 100 m of a stop line request the phase serving their lane.
    2. Master clocks: when a subsystem's cycle ends, the strategic layer computes the next cycle length from its CI, votes on the offset plan, and runs marriage logic with its neighbour. A married subsystem follows its partner's clock.
    3. Intersections: each loop meter adds unoccupied time and new vehicles during green. The current phase ends at its planned green or earlier by gap-out (except the coordinated phase), followed by amber and all-red. Skippable phases with no demand are skipped and their time carried forward.
    4. End of an intersection cycle: DS per phase is the highest DS among its strategic loops; the split plan is voted on; the next cycle length is chosen so the intersection drifts back to its offset (at most ±20% per cycle).
    from scats.runner import run, mode_config
from scats.scenarios import advanced

cfg = mode_config("scats", bus_priority=True)       # or "fixed", "actuated"
res = run(advanced(), cfg, "my_run", "results/mine", seed=3, gui=True)
print(res["avg_delay"], res["stops_per_veh"], res["bus_avg_delay"])

    Using your own network

    1. Build or import a network with netconvert (for example from OpenStreetMap) with the junctions you want as traffic_light.
    2. Add an inductionLoop named loop_<lane> near the stop line of every incoming lane.
    3. Write PhaseDef rules for each junction's phases. Rules map approach class and turn (s, l, r) to G or g; the controller builds SUMO state strings from the controlled links. Junctions with more than four arms need a custom approach classifier in Intersection.__init__.
    4. Group intersections into subsystems, pick a CI for each, and list neighbouring pairs that may marry.
